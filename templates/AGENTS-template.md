# AGENTS.md

本文件保留知识库独立使用时的必要约定，详细工作流由 llm-wiki skill 的对应策略定义。

---

## 目录结构

```text
.
├── AGENTS.md              # 本文件，管理 Schema 与核心工作约定
├── raw/                   # 原始素材层，包含正文、原始响应快照与附件
│   └── assets/            # 原始响应、图片、PDF、MP3 等附件，不作为素材页处理
│       └── YYYYMM         # 快照与附件按月存储在不同的子目录
└── wiki/                  # 生成的 Wiki 页面，遵循 llm-wiki 规范
    ├── analyses/          # query 的归档输出（YYYYMMDD - <topic>.md）
    ├── concepts/          # 概念页（术语、方法、原理等）
    ├── entities/          # 实体页（项目、工具、组织、人物等）
    ├── hubs/              # 主题聚合与结构化导航页
    ├── logs/              # 操作日志（YYYYMM.md，按月存储）
    ├── summaries/         # 对应 raw 素材的摘要页
    ├── index.md           # 全局索引
    └── overview.md        # 知识库概览
```

---

## 必要底线

- 本文件所在目录是知识库根目录。技能与工具另行定位，不能因终端切换目录而改变知识库目标；具体路径约定见 skill 的 `preflight.md`。
- raw 素材只追加新版本，历史正文始终只读；来源元数据维护遵循 skill 的 raw profile。
- 原始响应快照、图片、PDF 与其他附件保存到 `raw/assets/YYYYMM/`；附件不参与素材页的 frontmatter 校验或自动修复。
- query/explore 默认只读，用户明确要求保存时在授权范围内直接执行。
- 删除、重命名或批量改链接须先列明确切目标与影响范围并获准；重构授权不包含删除孤儿页。
- 写入 wiki 后维护必要索引，先执行只读 lint，再追加一条完成日志；失败时说明已写入文件和未完成事项。具体收尾遵循 skill 的 `lint-policy.md`。
- 日志只追加，历史日志不修复；日志追加失败不声明事务完整成功。

---

## 维护原则

- 素材新增、来源更新和未完成处理的补完统一使用 ingest。来源正文变化时必须执行 skill 的 `provenance-policy.md` 更新协议；重复输入也要检查上次传播是否完成，不能仅凭 raw 已存在就结束。
- 每次摄入检查核心实体与概念，搜索已有页及历史摘要；满足 skill 的 `synthesis-policy.md` 建页门槛时当次创建或更新，证据不足时保留可恢复的候选，不创建占位页。按该策略执行首次历史回扫和到期回扫，不能只生成摘要就结束。
- 优先维护同义的已有页面，按实际增量补充。重复素材不推进回扫计数；摘要与提炼检查均已完成时提醒已摄入，未完成时补完并如实记录。
- 每页围绕明确主题，分析与聚合可以涉及多个实体。完整短页无需扩写，无实际内容的可选小节可省略。
- 只为有意义的关系链接已存在页面，无需对每次术语出现都加链。查询、证据与来源更新分别遵循 skill 的 `query-policy.md` 和 `provenance-policy.md`。
- 论断可追溯到 raw，关键数字和引文核对原文后提供来源 id 与脚注。事实冲突保留双方观点及来源，使用 `conflict-note-template.md` 标记，不自动删旧保新。
