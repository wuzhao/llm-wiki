# LLM Wiki

**简体中文** | [English](README.en.md)

让 AI Agent 把零散素材整理成有来源、能更新、可查询的本地 Markdown 知识库。

本项目受 Andrej Karpathy 的 [LLM Wiki 构想](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 启发，采用「编译优先，按需检索」：先将素材整理为相互链接的知识页，再基于已有知识和原始证据回答问题。你提供素材与问题，Agent 负责整理和维护。

## 可以做什么

- 摄入本地文本、网页或粘贴内容，保留来源、采集时间和版本。
- 增量维护摘要、实体与概念页，追踪来源变化，保留历史和冲突。
- 基于库内证据回答问题、探索知识缺口，提供引用并说明不确定性。
- 检查链接、索引、证据与陈旧内容，按要求执行安全修复。

适合个人研究、团队技术知识积累和长期主题追踪。

## 让 Agent 安装

在 Codex、Antigravity、千问办公、WorkBuddy 等 Agent 中发送下面的指令。Agent 需要能够联网、读写本地文件并执行工具；本项目支持 macOS 和 Linux。

默认采用工作区级安装，技能与知识库使用独立目录。例如：

| 路径（相对当前工作区） | 用途 |
| ---------------------- | ---- |
| `skills/llm-wiki/` | 技能规则、模板与工具 |
| `我的知识库/` | 素材、知识页与日志 |

```text
将 llm-wiki 安装到当前工作区：
https://github.com/wuzhao/llm-wiki

读取仓库说明和 SKILL.md，优先使用当前 Agent 的工作区级技能目录；
不支持时，将完整项目放到 skills/llm-wiki，并提供显式加载指令。
技能与知识库目录分开，已有安装保留原位。
准备运行环境和依赖，验证工具，报告安装路径、验证结果及后续加载方式。
```

`skills/llm-wiki/` 是显式加载的位置示例，自动发现方式取决于所用 Agent。其他已有安装也可显式指定使用。

## 开始使用

以下示例使用当前工作区的技能与「我的知识库」，名称和素材路径可自行替换。新会话中，提供技能和知识库位置，必要时使用安装时返回的加载指令。

### 第 1 步：创建知识库

```text
使用当前工作区安装的 llm-wiki，新建独立的「我的知识库」空目录，
完成初始化和检查，告诉我实际保存位置。
```

> ⚠️ 注意：初始化只面向空目录，已有知识库直接打开使用。

### 第 2 步：提供素材

本地文件：

```text
将 /path/to/article.md 摄入「我的知识库」，整理摘要并更新相关知识页。
```

网页，将占位内容替换为实际 URL：

```text
将这个网页摄入「我的知识库」：<网页 URL>。
```

粘贴文本：

```text
将下面的内容摄入「我的知识库」。
标题：缓存的适用条件
正文：缓存可以复用已有计算结果，但需要明确命中条件与失效策略。
```

### 第 3 步：基于知识库提问

```text
基于「我的知识库」，解释缓存有哪些适用条件。
给出依据页面；来源存在分歧时，分别说明。
```

查询默认只读；需要保存回答时，追加「将回答归档到知识库」。

## 日常使用示例

### 更新已有素材

```text
重新摄入 /path/to/article.md 到「我的知识库」，更新受影响的页面，
保留历史与冲突，列出仍待复核的内容。
```

### 探索知识缺口

```text
查看「我的知识库」中关于缓存的内容，找出尚未回答的问题、
缺少的证据，以及值得继续研究的方向。
```

探索默认只读；需要落盘时，追加「保存探索结果」。

### 检查和修复问题

先检查：

```text
检查「我的知识库」的健康状况，报告问题与处理建议。
```

需要修复时：

```text
执行上次报告中的安全修复，复查并列出仍需人工判断的问题。
```

### 想自己操作

向 Agent 询问以下任务、模式或工具的用法：

| 操作 | 操作名称 | 用途 |
| ---- | -------- | ---- |
| 初始化 | `init` | 在空目录创建知识库基础结构与文件 |
| 摄入 | `ingest` | 保存素材，更新摘要与相关知识页 |
| 更新 | `reingest` | 保存新版本，复核受影响的页面 |
| 查询问答 | `query` | 综合证据回答并引用来源，默认只读 |
| 归档回答 | `query` +「归档/保存」 | 将回答保存为分析页 |
| 知识探索 | `explore` | 发现知识缺口、主题联系和结构治理建议，默认只读 |
| 保存探索结果 | `explore` +「保存」 | 保存分析或主题聚合页 |
| 检查 | `lint` | 只读检查结构、索引、证据、冲突与陈旧性 |
| 修复预览 | `lint --fix --dry-run` | 预览安全修复，不改文件 |
| 安全修复 | `lint --fix` | 执行能够确定处理的修复 |
| 清理内容 | `cleanup` | 按获准的确切目标删除内容、清理引用并检查 |
| 全文搜索 | `search` | 返回命中页面与片段，支持分页 |
| 影响分析 | `impact` | 只读列出来源变化影响的页面 |

归档和保存是对应工作流的选项；`search`、`impact` 是配套工具能力。具体调用方式由 Agent 根据当前实现确定。

```text
介绍 ingest、query、lint 和安全修复的用法，按本机环境给出手动步骤与命令，
说明哪些内容整理和问答步骤仍需要 Agent 完成。
```

## LLM Wiki 如何运行

Skill 提供规则与模板，工具负责素材保存、搜索、依赖分析和确定性检查，Agent 负责理解证据、整理知识页。操作前先确定技能位置与目标知识库。

### 编译、更新与查询

```text
ingest / reingest
[Files / URLs / Text]
         │
         ▼
[Agent with Skill rules]
         │
         ▼
[Ingestion tool] ▶ [raw/ and URL snapshots in raw/assets/]
         │
         ▼
[Agent: compile / update wiki/]
         │
         ▼
[Update index and Read-only lint]
         │
         ├─ blocking errors ▶ [Correct and recheck]
         ├─ pass            ▶ [Log completion and remaining warnings]
         └─ cannot finish   ▶ [Report writes and log incomplete status]

query / explore
[Question] ▶ [Agent: index and full-text search]
                              │
                              ▼
                [Read wiki/ and verify raw/]
                              │
                              ▼
          [Answer with citations / Research directions]
```

同一来源的相同内容已完整摄入时，返回既有页面；此前只保存了素材时，可以补完整理。知识页按实际增量维护，不要求每次新增概念。

来源更新后，Agent 结合依赖记录和全文搜索复核旧页面，区分当前结论、历史状态与冲突。归档分析保留历史正文，依赖变化时提示复核。查询分批阅读知识页，对关键数字、引文和冲突回查原始素材。

### 知识库如何保存

知识库独立于对话保存，知识页使用带 YAML 元数据的 Markdown，可直接查看。

| 位置 | 内容 |
| ---- | ---- |
| `raw/` | 原始素材层，素材页保存正文、来源地址或路径、采集时间与版本 |
| `raw/assets/` | 原始素材层内的网页原始响应快照与附件，不作为素材页处理 |
| `wiki/` | 摘要、实体、概念、分析、主题聚合、索引、概览与日志 |

索引定位内容，概览说明覆盖范围，月度日志记录操作及待复核事项。备份应包含完整知识库；日志是变更摘要，不能替代完整文件历史。手动修改知识页后，可让 Agent 检查引用与索引。

目录和字段见 [结构说明](references/schema.md)、[schema.json](references/schema.json)；Frontmatter 见 [OKF 0.2 profile](references/okf-frontmatter.md)。

### 使用边界

- 素材提取：网页保留代码、链接和普通表格，复杂表格保留 HTML。抓取不执行 JavaScript、下载网页图片或解析 PDF 等二进制附件；必要时提供可用正文。
- 原始素材：既有 raw 正文只读；`lint --fix` 仅补齐可确定的 `type`、`title`。其他元数据纠正须有来源依据并记录日志。
- 证据与覆盖：结构检查通过、原文出现相同数值都不能代替事实核验。分批阅读可继续推进；读取失败时说明缺口，局部结果不代表全库结论。
- 写入与修复：检查默认只报告，安全修复只处理确定性问题。删除、重命名或批量改链接需报告确切目标与影响范围，按授权处理。
- 完成与失败：严重错误需修正重查，非阻塞警告可保留并说明。已产生写入但无法完成时，记录未完成状态；日志写入失败则如实报告。多文件更新不保证整体原子性，失败不会自动撤销已完成的写入。
- 运行与数据：任务由你向 Agent 发起，网页变化需重新摄入，本地源文件变化可由检查发现。目录分开不等于权限隔离；远程模型如何处理读取的内容，取决于 Agent 配置及模型服务。
