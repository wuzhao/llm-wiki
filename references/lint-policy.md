# Lint Policy

lint 目标：发现结构、链接、知识关系、冲突和陈旧性问题，并仅自动修复确定性的安全子集。

## 调用方式

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/lint_wiki.py" "<KB_DIR>" \
    [--lint-dirs dir1 dir2 ... | --lint-files file1.md file2.md ...] \
    [--index-file path/to/index.md] \
    [--fix] \
    [--dry-run] \
    [--strict-sources] \
    [--fail-on error|warning|any] \
    [--report-file /path/to/lint-report.md]
```

- 默认模式和 `--dry-run` 只报告，不写文件。
- `--fix` 只执行本文列出的安全修复。
- `--fix --dry-run` 预览安全修复但不落盘。
- 目录、类型、关键小节和阈值统一读取 `schema.json`。
- 前置结构缺失时立即停止，不执行修复。
- `--fail-on` 按未解决问题决定退出码：`error` 包含严重问题，`warning` 包含严重及中等问题，`any` 包含全部级别。匹配时返回 1，运行失败返回 2；默认保留仅报告问题时返回 0 的行为。
- 目录遍历失败时报告覆盖不完整并返回 2，即使未传 `--fail-on`。整次 `--fix` 不写入知识库或追加修复日志，恢复读取后再重跑。
- `--report-file` 是显式导出报告，只写指定报告文件；报告必须在 raw、wiki 之外，不能覆盖 AGENTS.md 或符号链接。其他只读模式不写任何文件。

## 写后检查

本节是 init、ingest、synthesize、query 归档、explore 落盘与 cleanup 的共用收尾。Agent 先维护本次变更影响的索引条目和计数，保留手工说明；仅在领域分布、主要结论或近期重要事件变化时更新 overview，不为微小修改全量重写导航。然后执行：

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/lint_wiki.py" "<KB_DIR>" \
    --lint-files wiki/summaries/<本次变更页>.md wiki/concepts/<受影响页>.md \
    --fail-on error
```

- 文件清单使用知识库相对路径，覆盖本次新增、修改的 wiki 页面，以及全局引用搜索发现的受影响页面；修改过的 overview 也应列入。index 始终检查，无需重复列出。
- 删除或重命名后只列出现存页面，并包含引用旧路径或旧锚点的页面。无法确定影响范围时，改用目录检查或全库检查。
- 检查保持只读，不自动追加 `--fix`。严重问题返回 1，Agent 核对后在本次授权范围内修正并重查；无法修正或运行失败时，报告已写入文件和未解决问题，记录未完成状态。
- 返回 0 后追加本次 workflow 的完成日志；中等和轻微问题仍需在结果中说明。该检查验证结构、链接和索引，不证明知识论断正确。
- 一次 workflow 中相互依赖的变更只追加一条汇总日志。未通过且无法完成修正时记录未完成状态；日志追加失败时报告已写入文件，不声明事务完整成功。
- 写后检查只覆盖本次范围，不额外触发下述全库语义巡检。
- ingest 的主题检查与增量复核是编译流程的一部分，按 `synthesis-policy.md` 在本节之前完成。lint 通过不能替代提炼完成标准，未完成检查需如实记录。
- `lint --fix` 自身按现有专用入口记录修复及未解决问题，不递归触发另一次写后流程。

## 确定性检查

### Frontmatter

- 使用 YAML 解析器验证语法，不使用按冒号拆行的近似解析。
- `wiki/index.md` 按 OKF 0.2 根 index profile 校验，只保留 `okf_version`。
- 页面字段与 raw 元数据维护遵循 `okf-frontmatter.md` 的各类 profile。
- raw 同时存在 `resource` 与旧字段 `source_url` 且值不一致时，报告中等问题；不自动覆盖、删除或迁移来源地址字段。
- wiki 概念文档要求 `type` 为非空字符串，并按 `schema.json` 的路径映射校验和补齐；`title`、`description` 与 `tags` 作为本项目推荐字段检查。
- 重复键或无法解析的 YAML 只报告，整个文件禁止自动修复，包括链接与 index 条目。可修复字段按解析位置替换，保留未知字段；涉及锚点或别名且无法保证其他字段不变时，保留原文并报告。
- 来源摘要已提供 `synthesis` 时，校验其格式并报告检查指纹与当前内容不一致；旧摘要未提供时不当作结构错误。不自动补齐或刷新检查记录，也不据此判断建页质量。

### 链接

- 页面身份使用知识库相对完整路径。
- 同时检查标准 Markdown 链接与 Wikilink。
- raw 正文中的链接仅报告，不执行替换，也不计入已自动修复项；核对时需区分原始来源的链接基准与知识库本地路径。
- 检查目标文件、同名歧义和标题锚点。
- 自动修复候选只能来自原链接意图指向的 `link_roots` 范围，不得跨素材正文、`raw/assets/` 附件与 wiki 猜测，也不得修向模板、脚本或知识库外部；嵌套目录以最长路径前缀识别归属。
- 省略目录的链接只有在目标清单完整、且同一链接根目录内唯一匹配时才允许自动修复。
- 标准链接覆盖行内链接、图片和引用定义；支持当前页 Wikilink 锚点。代码围栏、缩进代码、行内代码、注释与 frontmatter 不作为正文链接修复。
- 修复仅替换链接目标，保留标题、别名和外围语法；候选锚点也必须存在。未识别的复杂 Markdown 语法保留原文，不能把脚本当作完整渲染器的替代品。
- `sources[].resource` 单独校验本地来源路径与锚点，只报告，不猜测或改写；外部 URI 不发起网络探测。来源关系不计入普通知识入链。

### Index 与孤儿页

- index 按完整路径与实际内容页对比。
- 缺失 index 条目可以安全补齐，并带标题与单句摘要。
- 检查重复条目、已知分区中的错误归类，以及存在的统计行是否与全库实际内容页数量一致。三者只报告，不自动删除、移动条目或改写统计。
- 引用式 Markdown 链接按正文中的使用位置归类、判重并报告行号；定义位置只用于解析目标，同一个定义可对应多次使用。
- 孤儿页定义为「没有其他内容页指向此页」。
- index、overview、logs 和页面自链接不计入知识入链。
- 同时保留 index 缺失和孤儿页两个独立问题类型。
- `--lint-dirs` 与 `--lint-files` 互斥，前者限制目录，后者限制到 raw 或 wiki 内现存的 Markdown 文件并始终检查 index；附件目录 `raw/assets/` 不作为内容扫描范围，显式选择其中的目录或文件会被拒绝。完整 index 和全库关系仍需读取，同次调用复用已读取的 Markdown，供检查、来源图、锚点和入链使用，避免反复加载全库。全库关系读取失败时，不给出孤儿页结论；目录覆盖不完整时也不判断索引统计。index 补条目仍使用所选目标页，不能重复加入已有条目。

### 冲突

- 检查标准冲突块是否包含观点 A、观点 B、双方来源、当前状态。
- 对「并存」「待处理」「open」等状态报告未解决冲突。
- 对包含明显冲突语句但没有标准冲突块的页面报告冲突候选。
- 所有冲突项保持 report-only，不自动裁决或改写观点。

### 陈旧性

- `stale_after` 到期时报告陈旧页面。
- 按 OKF 0.2 读取 `verified[].at`、`generated.at` 与 `stale_after`；为旧页面兼容读取 `verified_at`、`last_reviewed` 与 `timestamp`。
- 页面超过 `schema.json` 的复核周期且没有更新验证信息时，报告待复核。
- `status: deprecated` 页面保留历史，但不重复报告陈旧性。
- 本地来源继续使用 `source_file_sha256` 检查源文件变化。
- 外部原文件不可访问默认报告警告，表示无法检查来源更新，不否定已保存的 raw 证据。需要持续监控本地来源时使用 `--strict-sources` 将不可访问升级为严重错误；库内 raw 或原始响应损坏始终为严重错误。
- 同一来源仅对最新 raw 检查当前本地文件，兼容旧页面中由路径、URL 与采集时间推断的来源版本；历史 raw 仍校验自身 `body_sha256` 与原始响应快照。

### 来源证据与依赖

- 按 `provenance-policy.md` 检查知识页来源缺失、循环证据、是否到达 raw、逐条引用的来源 id、脚注定义缺失或重复，以及关键数值或引文是否能在指定来源链中定位。
- 按来源正文指纹、来源版本及旧页面的生成时间，报告直接和传递依赖的待复核状态；归档分析只报告，不覆盖历史正文。
- 字面值检查只产生候选，不能当作事实真伪判定；所有来源、事实与依赖问题均保持 report-only。

### 页面结构与体积

- 关键小节和所有体积阈值读取 `schema.json`。
- 报告空正文；不按最少字数判定知识价值，不要求为填满模板而扩写或补造关系。
- 日志超过阈值时建议开启新分片，不移动、删除或截断历史记录。

## 语义检查

健康检查 workflow 中，Agent 在脚本扫描后对用户要求的主题或范围执行语义复核；大库按主题分批，报告实际覆盖范围：

- 同一实体或概念页中来自不同来源的事实是否互相否定。
- 新来源是否使旧结论失效，或仅增加适用条件和时间范围。
- 同主题页面是否存在未建立链接的重复论断。
- 高频术语是否值得建立独立页面。

主题提炼的建页与暂缓标准见 `synthesis-policy.md`。语义检查可以发现遗漏候选，但 `lint --fix` 不创建知识页、不推进回扫检查点；用户明确要求整理或提炼时使用 synthesize workflow。

默认输出候选、证据和建议。已有明确写回授权时，在授权范围内使用 `templates/conflict-note-template.md` 记录冲突；没有授权时先提供具体建议再询问。

## `--fix` 安全子集

- 补齐可从目录唯一推断的 `type`。
- 补齐缺失的 `title`。
- 修复 wiki 页面中指向知识目录内唯一匹配目标的失效链接。
- 为 index 补充缺失的内容页条目。
- 创建缺失的当月日志，并追加本次 lint 统计。

raw 的安全字段与正文边界见 `okf-frontmatter.md`，脚本不替换来源正文。

历史日志只读，即使显式 `--fix` 也不得补字段或修改正文链接。当月日志通过专用追加入口写入，拒绝符号链接目标。

扫描快照、检查与修复计划、报告、提交执行分别处理。页面修复先验证全部写入目标和原文，逐页写入前再检查是否发生变化，发现扫描后的编辑时停止，不覆盖新内容；这不替代编辑器之间的并发锁。写入使用同目录临时文件原子替换。多文件操作不保证整体原子性；部分写入或日志追加失败时，返回失败并列出已写入页面，不能声明事务完整成功。

## 禁止操作

- 自动解决或删除冲突观点。
- 删除 source、entity、concept 或其他知识页面。
- 级联删除引用页面。
- 截断、移动或清理历史日志。
- 在多候选情况下猜测链接目标。
- 跨素材正文、`raw/assets/` 附件与 wiki 选择同名候选。
- 将链接修向 `raw/`、`wiki/` 之外。

## 报告要求

报告按严重、中等、轻微分级。带 `--fix` 时区分「自动修复」和「需要人工介入」；不带 `--fix` 时只显示问题详情。位置使用 `[[知识库相对路径]]:行号`。

## 日志

每次 `--fix` 都向 `wiki/logs/YYYYMM.md` 追加统计记录。当月日志不存在时先按 `templates/log-template.md` 创建，再追加本次记录。
