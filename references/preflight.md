# Preflight

执行任何 LLM Wiki workflow 前先做硬校验。

## 运行位置与工具路径

- `WORKSPACE_DIR` 是用户当前工作的工作区根目录；`SKILL_DIR` 是实际加载的 `SKILL.md` 所在目录；`KB_DIR` 是本次目标知识库根目录。分别解析为绝对路径，不能因切换命令目录而改变目标，`KB_DIR` 不得与 `SKILL_DIR` 相同。
- 新安装优先使用当前 Agent 的工作区级技能目录；不支持时，可在工作区的 `skills/llm-wiki/` 保留完整项目并显式加载。新知识库使用独立目录，技能不放入知识库。已有安装不自动迁移或覆盖，用户明确指定的位置可继续使用。
- `references/`、`templates/` 与 `scripts/` 均相对 `SKILL_DIR` 定位；知识页、索引、日志及 CLI 文件范围参数相对 `KB_DIR` 定位。用户提供的相对素材路径相对其工作区或明确给出的基准解析，再以绝对路径传入工具。
- `<PYTHON>` 表示已验证的 Python 3.10 及以上解释器绝对路径。优先复用 `SKILL_DIR/.venv/bin/python`，否则使用已验证且依赖齐备的解释器；准备依赖与执行工具使用同一解释器。
- 本项目中的调用示例使用 `"<PYTHON>" "<SKILL_DIR>/scripts/<工具>.py" "<KB_DIR>"`。替换为实际绝对路径并作为独立参数传入，保留空格和中文路径；不依赖终端当前目录或裸 `python3` 恰好指向正确环境。首次使用或环境改变后验证工具，不能以模型判断代替执行结果。

## A. init 场景

先确定新知识库的独立目标目录，不能在技能目录内初始化或将已有工作区文件当作待覆盖内容。初始化时，若部分目录或关键文件（如 `AGENTS.md`）已存在，则停止执行，并建议用户在空目录进行初始化，避免破坏已有文件。

## B. 非 init 场景

必须存在 `references/schema.json` 中 `required_paths` 定义的全部目录和文件。

`scripts/wiki_config.py` 提供共享的 `validate_structure` 检查，各 CLI 均调用。可复用当前调用的检查结果；仅在手工校验时读取 schema 并逐项核对。检查同时验证文件与目录类型，以及解析符号链接后的路径是否仍在知识库内。参数错误、空正文或结构不完整均不得创建目录或素材文件。

任一缺失则立即停止，并返回：

- 缺失项清单

- 建议先执行初始化 workflow（按 `references/schema.json`、`references/schema.md` 与 `references/init-files.md`）

## C. 参数解析

- 对话中的知识库名称或路径由 Agent 解析，不能仅因素材首参是目录就把它视为知识库。优先使用用户本次明确指定的目标，其次复用当前会话已确定的目标。
- 只有当前工作区根目录本身通过结构校验、且与技能目录不同，才能在未显式指定目标时将其作为已有知识库。不能将脚本运行目录或素材所在目录隐式用作 `KB_DIR`。
- 仅提供知识库名称时，相对 `WORKSPACE_DIR` 定位；有多个同名候选或无法确定目标时，列出候选并请求必要信息，不猜测写入目标。
- 各 CLI 均显式传入已确定的 `KB_DIR` 绝对路径。首次写入或切换目标时说明实际目标路径；用户已明确授权该目标时直接执行，无需额外确认。

## D. 失败处理

- 前置检查失败时不写入任何文件。
- 输出可执行的下一步，而不是泛化提示。
