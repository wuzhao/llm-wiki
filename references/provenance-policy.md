# 来源证据与增量更新

本策略适用于 ingest、synthesize、lint 与需要核对原文的 query。结构与链接校验不能代替事实核验。

## 来源记录

- `sources` 使用可回查的页面或 raw 路径；逐条引用使用唯一、稳定的 `sources[].id`。
- 重要数字、日期、直接引文写入前先定位 raw 原文。逐条引用的范围按下节的来源结构确定，使用 `[^来源-id]` 并提供唯一的 `[^来源-id]: ...` 脚注定义；在强制逐条引用的范围内，只有 sources 中的 id 不足以形成完整脚注。
- 逐字引用须明确标注，例如 `原文：「...」`、`原话是「...」`、`作者写道：「...」` 或引用块中的 `> 「...」`。术语、译名、强调和作者归纳也可使用引号，但不因此自动视为逐字引文；其准确性由语义复核判断。
- 新建或实质更新来源引用时，推荐记录 `sources[].body_sha256`，表示本次实际读取的来源正文指纹。通过 `scripts/impact_wiki.py` 获取，不凭空生成。
- 仅支撑已明确标注为历史的内容时，可在对应来源条目设置 `historical: true`。该来源仍参与证据回查，但不向当前结论传播新版告警；不得用此字段掩盖尚未核对的当前论断。
- 摘要、实体、概念、分析与含事实论断的聚合页，其来源链应能到达 raw。纯导航页不因缺少 `sources` 被当作无证据论断。
- 派生页面之间不得形成循环证据。来自同一原文的转载或多层摘要不能当成多份独立实验。

```markdown
---
type: concept
title: 查询延迟
sources:
  - id: experiment-a
    resource: ../summaries/experiment-a.md
    body_sha256: <实际读取的来源正文 SHA256>
---

实验 A 报告延迟为 42ms。[^experiment-a]

[^experiment-a]: 实验 A 的原始结果，适用条件见来源摘要。
```

## 逐条引用的适用范围

来源结构决定引用粒度，页面类型作为默认判断依据：

- 单源摘要：`sources` 仅有一项，直接指向一个可读取的 raw 快照时，忠实转述的普通数字和日期可使用页级来源，不要求每行重复脚注。仍须保留原文的单位、限定词、时期和适用条件。
- 多源摘要：合并多个 raw，或经其他知识页间接引用时，不自动获得上述豁免；关键数字、日期与直接引文须逐条引用。只有一个来源条目，但该条目汇集多个 raw，也属于此类。
- 概念、实体、分析与含事实论断的主题聚合页：关键数字、日期与直接引文保留逐条引用要求。单篇素材也可能经过二次加工，不仅凭来源数量自动放宽。纯链接导航无需补造来源或脚注。
- 任何知识页的校准值、派生值与直接引文都须就地标注。校准值保留原值、采用值、原因与支持改动的实际依据；派生值列出有来源的分量、算法和条件；直接引文能沿指定来源定位原句。

一个论断或一行表格可以共用末尾脚注，整表共享来源按下节的有界规则执行，不要求每个数字重复标注。raw 原文和历史日志继续只读，不回填知识页脚注。

lint 对可确认的单源摘要免报普通转述的缺脚注提示，同时继续对照其唯一 raw 检查数值与引文。已有逐条脚注仍按该脚注的来源核验，未知 id、缺失或重复定义不会因豁免而放行。校准、派生说明及公式等可识别的加工标记继续触发逐条引用要求；脚本无法穷尽语义，Agent 仍须核对实际加工行为，不能因数字恰在原文出现就认定无需脚注。

## 数据密集页面与派生值

同一论断的多个数字可以共用末尾脚注，不要求每个数字重复挂脚注。多来源汇编优先按指标、时期与地域拆成表格行，各行标明实际来源；一个来源不能替代其他行的证据。

仅当紧邻的整张表确实共用来源时，允许以下显式范围：单独一行 `本表来源：[^来源-id]` 或 `本表数据来源：[^来源-id]`，后接带首尾竖线和标准分隔行的 Markdown 表格，中间最多一个空行。该范围只覆盖这一张连续表格，下一段和下一张表不继承；行内自带脚注时以该行的逐条脚注为准。仍须提供 sources id 与脚注定义。普通「来源」段落或前一段脚注不会成为表格默认来源。

```markdown
本表来源：[^survey]

| 指标与时期 | 原文值 | 采用值 | 处理说明 |
| ---------- | -----: | -----: | -------- |
| 样本 A，调查当期 | 0.563% | 5.63‰ | 精确换算：0.563 × 10 |
| 样本 B，调查当期 | 0.4% | 4‰ | 精确换算：0.4 × 10 |

[^survey]: 调查原文及适用范围，对应 sources 中的 survey。
```

涉及计算、校准或推断时，按需增加证据表，记录「指标、时期、地域」「原文表达」「采用值」「处理方式」「依据与来源」。保留以下区别：

- 直接摘录：保留原文含义、限定词与单位，避免把不同指标拼成一条无法回查的长句。
- 精确换算：列出原值、公式与单位，例如百分率乘以 10 后以千分率表达。lint 只对已支持的确定等值关系放行；一般算术推导仍须阅读公式及有来源的分量。
- 原文单位省略：核对上下文能否支撑补全，写明补全依据；不能仅凭数字相同自动认定单位。
- 校准：原文 `5.63%` 被采用为 `5.63‰` 属于改动事实表达，须保存原文并另引能支持改动的实际依据。只有「按常识校准」的自述不足以消除证据缺口。
- 推断或证据不足：明确标注推断方法、条件或待核验状态；不补造统计公报、脚注或原始证据，不以填表本身免除告警。

lint 的「引用完整性」表示脚注或来源关联不完整，尚未核对该论断的证据；不表示数字已在来源中找到。「证据待复核」按具体主张展示单位差异、单位省略、无可比较候选或直接引文措辞未定位，并附可找到的 raw 候选位置与上下文。数值部分相同的候选仍可能属于其他指标或时期，只供回查，不能自动认账。

证据诊断同时区分限定词差异和年份缩写歧义。例如原文 `1.3 到 1.5 左右` 对论断 `1.3 至 1.5`，数值相同且仅普通近似词不同，保留蓝色表达建议；原文 `15 年` 对论断 `2015 年` 可作为回查候选，但也可能指时长或其他世纪，保持黄色待复核，不自动补世纪。数据密集不构成免检理由，不能用同一来源中的其他数值或主张密度抵消证据缺口。

跨页反复出现同一处原文候选时，报告汇总回查入口并保留所有影响位置。汇总键包含来源路径、正文指纹、原文跨度、诊断类型与主张表达；多个候选尚未消歧时不合并。该汇总不是事实批准记录，不减少告警计数，也不能替代逐处归因核对。

## 证据候选的分级与处置

| 候选类型 | 级别 | 处置 |
| -------- | ---- | ---- |
| 数值、正负号、单位与范围相同，仅精确表述和「约、左右、上下」等普通近似词不同 | 🔵 建议 | 核对断言强度，不自动视为原文精确支持 |
| 上下界、序数、年份缩写或「近」等带方向的限定不同 | 🟡 待复核 | 核对边界、时间与含义，不能按近似词统一降级 |
| 单位不同、单位省略或补全、直接引文措辞未定位 | 🟡 待复核 | 回查实际依据，不以校准自述或相同数字代替证据 |
| 未找到可比较的数值候选 | 🟡 待复核 | 按页核对上下文，区分缺来源、派生值、作者归纳与暂不支持的格式 |

每条脚注论断片段仍只计一项，以其中最高级别为准；同段含普通近似建议和单位等实质风险时，整项保持黄色，详情分别显示主张级别。近似候选同时存在边界、单位或序数差异候选时，不按低风险候选自动降级。直接引文继续核对原始措辞。

无单位的小整数原本就不作为关键数值触发检查。「一人、一项、两次」有明确计数单位，可能涉及人数、事故、失败次数或条件数量，不因数字小或仅有计数就整体降级。作者自行归纳的条目数由 Agent 核对本页清单，不能把所有小计数预判为词法噪声；日期格式只有已实现且能确定等价时才匹配，不按猜测补齐区间。

### Agent 分流与复核复用

脚本候选先交由 Agent 阅读上下文，不逐条要求用户判断。明确的泛指表达（如「提出一个问题」）、作者自行组织的条目数与编号，由 Agent 核对语义或本页清单；归属于来源作者的分类仍须核对原文。译文数量核对原文计数对象、条件与单位。仅剩来源缺口、冲突、需要补充材料或超出授权的内容取舍时，才向用户提交具体决策项。不能因总告警数减少而宣称事实已验证。

可使用 lint 的 `--review-template` 将本轮候选导出到知识库之外的新 JSON 文件，再由 Agent 完成语义复核。导出状态全部为 `pending`；读取已有有效记录时保留其结论。`--review-file` 显式读取记录，不扫描日志自动推断批准，不写入知识库。记录结构如下：

```json
{
  "version": 1,
  "records": []
}
```

逐条保留工具导出的 `id`、`page`、`claim`、`kind`、`context`、`line`、`dependencies` 与 `rules`，只填写复核字段：

- `status`：`pending`（未解决）、`supported`（指定来源支持该处表达）、`non-quantity`（语义上非数量主张）或 `author-structure`（作者自行组织的结构）。后两者不能用于豁免真实的人数、次数、金额或事件顺序。
- `reason`、`reviewer`、`reviewed_at`：具体依据、实际复核者和 ISO 时间；已复核项必填。Agent 可在授权范围内完成复核，无需将每项例行判断交给用户。
- `evidence`：`[{"path": "raw/来源.md", "quote": "实际原文片段"}]`；`supported` 必须提供，其他状态可为空。工具验证片段仍存在于该论断的 raw 来源范围内，但语义支持关系仍由复核者负责。

复核绑定整页、直接及传递来源内容指纹和检查器规则指纹；任一变化、读取不完整或原文片段失效均不复用。纯导航调整也可能使整页指纹变化，这种保守失效优先于误用旧结论。未出现在本次范围内的记录提示为未复用，不代表其事实结论被否定；导出只包含当前扫描候选，不能直接覆盖全库旧记录。

有效记录在工作台显示为「已复核」，原始诊断、严重级别、告警计数与 `--fail-on` 退出码保持不变。它是有依据的复核结果展示，不是脚本的事实认证，也不是通用词语豁免。校准值和派生值缺少实际来源时保持 `pending`，不能通过复核文件绕过补充来源的要求。

已核对的校准值应摄入或引用支持采用值的实际 raw 证据，并让对应论断的脚注沿来源链到达它。只在页面 sources 中增加无关条目，或把依据写在知识库之外，不能替代该条引用。外部依据是否覆盖全部指标、期间和地域仍需逐项判断，不承诺加入一份公报就能消除所有单位候选。

派生值列出真实分量、方法与条件后，由 Agent 完成语义复核；lint 不证明一般算术，保留候选不等于已确认错误，也不应把自行计算的结果伪装成原始来源来消除提示。候选是否合理取决于是否指出具体风险、回查位置与处置动作，不能只看是否可以清零。未定位项按页列为复核队列，优先核对影响结论的主张，不只在高密度页面检查，也不把未定位整类认定为低价值噪声。

## 影响分析

在来源更新后执行只读分析：

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/impact_wiki.py" "<KB_DIR>" --source raw/<新版本>.md
```

输出包括来源正文指纹、同一来源各版本所影响的传递依赖，以及需要保留为历史快照的分析页。读取失败必须说明，不能把不完整结果宣称为完整影响范围。

## 更新协议

ingest 检测到同一来源正文变化时必须执行本节，不依赖用户额外发出更新指令。已有 raw 但上次传播未完成时，也应在补完分支重新核对影响范围，不能仅因本次素材未变化而退出。

第 1 步：读取旧 raw、新 raw、对应摘要与影响清单。再全文搜索实体名、别名及被修改的具体论断，补足尚未建立 `sources` 关系的相关页面。

第 2 步：逐页判断新增信息、适用条件变化和当前状态变化，执行必要的小范围更新。已有结论仍有效时可以只补来源或链接，不要求新增概念或大改正文。

第 3 步：明确区分当前有效结论、已被替代的历史状态、仍未解决的观点冲突。保留历史与来源；已被新版本明确替代的事实不继续作为当前事实呈现。归档分析保留历史正文，通过依赖报告提示待复核，不自动覆盖。

第 4 步：对已核对页面更新来源引用、指纹及有意义的内容更新时间；尚未核对的页面不能通过刷新时间或指纹伪装为已更新。

第 5 步：按 `lint-policy.md` 执行共用写入收尾。日志分别列出已更新、无需正文改动与待复核的页面及原因；仍有重要传播任务未完成时明确说明，不声明全部更新完成。

## lint 与查询的边界

- lint 报告缺少来源、无法到达 raw、循环引用、无效逐条引用、依赖正文变化和数值或引文证据待复核项；不自动补造来源或修正事实。
- `body_sha256` 直接发现正文变化；旧页面未记录指纹时，使用来源 `generated.at` 晚于派生页的时间作为待复核信号。
- 旧 raw 的来源出现新版本且正文内容不同，会使相关摘要及其传递依赖进入待复核报告。历史 raw 不再因与当前本地源文件不同而反复提示重新摄入，但仍检查自身正文与保存的原始响应是否损坏。
- 数值候选按完整数量匹配，在该条脚注指向的 raw 来源链中查找；豁免逐条脚注的单源摘要内容仅在其唯一 raw 中查找。不用子串包含判断或其他来源的数字抵消告警。匹配时保留数值、正负号、单位、范围及紧邻数值的近似或上下界限定；`50%` 不等同于 `150%`、`-50%`、`50 个百分点` 或 `约 50%`，百分比与千分比按精确比例换算，`0.563%` 与 `5.63‰` 等价，`5.63%` 与 `5.63‰` 不等价；百分点保持独立含义。
- 链接目标、链接 title 属性、引用定义和脚注 id 不作为论断。来源或相关阅读等明确导航区域的链接标题也不触发数值或引文核验，但链接外的描述与普通正文中的可见数值仍须核对；链接有效性由链接检查独立验证。
- 确定的等价写法可匹配：带单位的中文数字（二与两、十百千万亿、点式小数、四位数字年份）、`百分之`、全角数字、合法千分位、数值与单位间的空白，以及明确的单位换算。例如 `两个` 与 `2 个`、`百分之五十` 与 `50%`、`四十二毫秒` 与 `0.042 秒`。时间支持毫秒、秒、分钟、小时；存储量的 MB/GB/TB 按十进制、MiB/GiB/TiB 按二进制分别换算，不跨两组推断。单位和范围须能完整解析，不根据上下文猜测。
- 数量比较支持明确繁简字符别名，如 `億／亿`、`萬／万`、`兩／两`、`個／个`、`小時／小时`。英文整数数词支持零至十九、整十及规范的 hundred、thousand、million、billion 组合；明确的 second、minute、hour、year、month 单复数可按对应单位比较，保留正负、范围和限定词。`two months` 对应「两个月」，不匹配「两个」。不支持的英文小数词表达保持完整候选，不截取其中的整数来匹配。
- 英文 file、folder、resource 计数与中文通用量词之间只生成黄色「跨语言计数候选」，不自动确认对象相同；time/times 可能表示次数或倍数，也只提供候选，Agent 须阅读双方语境。`成千上万`、`成百上千` 不截成确定数量；`上下文` 中的「上下」不作为近似限定。此类抽取修正不豁免时长约数或序数，也不放行两位年份补世纪。
- 限定词先遵守词语边界：「逾」对应严格大于，「不逾／未逾」对应不超过，「逾期」不是数量限定词。明确动词短语 `pore/pores/pored/poring over` 中的 over 不当作大于，独立的 `over 35 years` 仍保留严格大于含义。`找不到一个` 保留完整谓语与计数，未原样定位时交给 Agent 核对否定范围和对象，不截取「不到」产生数量上界冲突，也不能仅凭原文出现「一个」自动通过；`人数不到 3 人` 仍按严格小于核验。直接引文继续核对原始措辞。
- 明确的口语符号也保留正负含义，`负的 2.41%` 与 `-2.41%` 等价，不能作为正 `2.41%` 的证据；`正的` 同样按正号解析。单位差异不因此放行，直接引文仍要求原始措辞。
- 完整日期按同一日历日期匹配，例如 `2026-06-07`、`2026 年 6 月 7 日`、`二〇二六年六月七日`、`June 7, 2026` 与 `7 Jun. 2026`。保留完整日期区间和近似、前后界限，不拆取日期中的年月日抵消其他主张；`06/07/2026` 等月日顺序不明的写法、非法日期及省略年份的区间仅允许完整原样定位，不推断日期或补齐端点。明确引文中的日期仍须符合原始措辞。
