# 复核记录工作流

用于将实际核对过的证据结论留给下次检查复用。本文件统一定义记录格式、分级与失效条件，来源编译规则见 [来源策略](provenance-policy.md)，报告选项见 [Lint Policy](lint-policy.md)。工具不会从日志、普通 Markdown 报告或历史对话自动推断批准。

## 第 1 步：查看摘要并导出候选

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/lint_wiki.py" "<KB_DIR>" \
    --review-template "/outside-kb/reviews-new.json" \
    --report-file "/outside-kb/lint-full.md"
```

模板须导出到知识库之外的新文件。JSON 顶层结构为 `{"version": 1, "records": []}`，每个新候选的状态为 `pending`。终端显示摘要，完整报告保留每个问题的位置、来源范围、原文候选与 id。

## 第 2 步：按页阅读证据

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/lint_wiki.py" "<KB_DIR>" \
    --report-page wiki/concepts/example.md --report-category evidence
```

此处只筛选显示，扫描与退出码仍覆盖原范围。先核对主张所指对象、时期、单位、限定条件与实际原文，再判断 supported、non-quantity、author-structure 或继续 pending；同值和同词不能代替语义核对。

## 第 3 步：填写已经完成的复核

保留模板记录的 id、page、claim、kind、context、line、dependencies、rules、review_policy 和 category。各字段的填写要求如下。

- `status`：`pending`（未解决）、`proposed-supported`（自动复核提议，待人工确认）、`supported`（指定来源支持该处表达）、`non-quantity`（语义上非数量主张）或 `author-structure`（作者自行组织的结构）。后两者不能用于豁免真实的人数、次数、金额或事件顺序。
- `reason`、`reviewer`、`reviewed_at`：具体依据、实际复核者和 ISO 时间；已复核项必填。Agent 可在授权范围内完成复核，无需将每项例行判断交给用户。
- `evidence`：`[{"path": "raw/来源.md", "quote": "实际原文片段"}]`；`supported` 和 `proposed-supported` 必须提供，其他状态可为空。默认验证片段仍存在于该论断的 raw 来源正文内；元数据与跨页取证按本页的元数据与跨页规则显式指定，不从全库任意寻找同值。语义支持关系仍由复核者负责。
- `evidence_options`：工具导出的只读回查入口，包含元数据字段及跨页路径，不代表已核验，不得直接整组复制为批准依据。

下例展示 direct 类记录的填写部分。将占位内容替换为实际核对结果，并保留模板中的其他字段。

```json
{
  "status": "supported",
  "reason": "<实际核对的对象、期间、单位与支持关系>",
  "reviewer": "<实际复核者>",
  "reviewed_at": "<本次实际 ISO 时间>",
  "evidence": [
    {"path": "raw/example.md", "quote": "<该条来源范围内实际存在的原文片段>"}
  ]
}
```

derived、approximate 类自动复核必须使用 proposed-supported，预填 source_values 和 derivation 或 approximation_span；缺少字段不能提交提议。指定复核者逐条核验后改为 supported，并填写 human_confirmation 的 reviewer 与 confirmed_at，疑难时交用户裁决。具体分类与字段见 [增量分类与人工确认](#增量分类与人工确认)。

泛指或作者自行组织条目可以使用对应状态并写清理由。缺材料、真实冲突或尚未核对的候选保持 pending。已有 Markdown 复核报告只能作为线索，仍需确认当前页面与原文后填写。

报告与模板的 `evidence_options` 会列出可用的元数据和跨页回查入口。以下为两种证据条目示例，须替换为本次实际核对的路径、字段和值：

```json
{"path": "raw/video.md", "field": "duration", "quote": "16 秒"}
```

```json
{"path": "raw/team.md", "via": "wiki/summaries/team.md", "quote": "总共不到200人"}
```

`field` 指向 raw 的时间或时长字段，`quote` 填完整字段值；`via` 必须是本条论断片段中的有效知识页链接，其来源链必须到达 `path`。两者可以组合。先核对元数据含义、主张归因与上下文，再填写 reason；可用入口不等于已支持。具体字段和边界见 [元数据与跨页复核入口](#元数据与跨页复核入口)。库外核验依据仍须先入库，不用复核记录代替真实来源。

## 第 4 步：加载记录验证

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/lint_wiki.py" "<KB_DIR>" \
    --review-file "/outside-kb/reviews-new.json" --fail-on warning
```

摘要会分别显示原始告警数、已有有效记录的主张数和仍待复核数。提议继续计入待复核。`--fail-on warning` 使用复核后的告警级别。使用 `--details` 查看逐条理由与原文。

## 第 5 步：后续检查继续复用

每次显式传入 `--review-file`；需要导出新候选时同时传入 `--review-template` 并使用新的文件名，有效记录会保留在新模板中。页面、传递来源（含元数据、跨页链接页及其来源）或检查规则变化后，对应记录会失效，重新核对后再填写。

局部扫描导出只包含本次范围的候选，不能覆盖全库旧记录。需要更新全库记录时使用全库扫描导出到新文件，保留旧文件供回查。复核记录不会补齐知识页来源，也不会修改 raw、wiki 或日志。

## 复核契约与诊断解释

lint 的「引用完整性」表示脚注或来源关联不完整，尚未核对该论断的证据；不表示数字已在来源中找到。「证据待复核」按具体主张展示单位差异、单位省略、无可比较候选或直接引文措辞未定位，并附可找到的 raw 候选位置与上下文。数值部分相同的候选仍可能属于其他指标或时期，只供回查，不能自动认账。

证据诊断同时区分限定词差异和年份缩写歧义。例如原文 `1.3 到 1.5 左右` 对论断 `1.3 至 1.5`，数值相同且仅普通近似词不同，保留蓝色表达建议；原文 `15 年` 对论断 `2015 年` 可作为回查候选，但也可能指时长或其他世纪，保持黄色待复核，不自动补世纪。数据密集不构成免检理由，不能用同一来源中的其他数值或主张密度抵消证据缺口。

跨页反复出现同一处原文候选时，报告汇总回查入口并保留所有影响位置。汇总键包含来源路径、正文指纹、原文跨度、诊断类型与主张表达；多个候选尚未消歧时不合并。该汇总不是事实批准记录，不减少告警计数，也不能替代逐处归因核对。

## 证据候选的分级与处置

| 候选类型 | 复核前级别 | 处置 |
| -------- | ---- | ---- |
| 数值、正负号、单位与范围相同，仅精确表述和「约、左右、上下」等普通近似词不同 | 🔵 建议 | 核对断言强度，不自动视为原文精确支持 |
| 上下界、序数、年份缩写或「近」等带方向的限定不同 | 🟡 待复核 | 核对边界、时间与含义，不能按近似词统一降级 |
| 数值相同，仅单位省略或补全 | 🔵 建议 | 核对原文语境中的单位，不自动接受补全 |
| 单位不同 | 🟡 待复核 | 回查实际依据，不以校准自述或相同数字代替证据 |
| 数值或直接引文未定位 | 🟡 待复核 | 复用当前内容哈希绑定的复核；哈希失配自动回到 🟡，队列保留供抽查 |

每条脚注论断片段仍只计一项，初始级别取各主张的最高级别；同段含普通近似或单位补全建议和单位不同等实质风险时，整项保持黄色，详情分别显示主张级别。建议类候选同时存在边界、单位不同、年份缩写或序数差异候选时，不按低风险候选自动降级。直接引文继续核对原始措辞。

无单位的小整数原本就不作为关键数值触发检查。「一人、一项、两次」有明确计数单位，可能涉及人数、事故、失败次数或条件数量，不因数字小或仅有计数就整体降级。作者自行归纳的条目数由 Agent 核对本页清单，不能把所有小计数预判为词法噪声；日期格式只有已实现且能确定等价时才匹配，不按猜测补齐区间。

### Agent 分流与复核复用

脚本候选先交由 Agent 阅读上下文，不逐条要求用户判断。明确的泛指表达（如「提出一个问题」）、作者自行组织的条目数与编号，由 Agent 核对语义或本页清单；归属于来源作者的分类仍须核对原文。译文数量核对原文计数对象、条件与单位。仅剩来源缺口、冲突、需要补充材料或超出授权的内容取舍时，才向用户提交具体决策项。不能因总告警数减少而宣称事实已验证。

复核绑定整页、直接及传递来源内容指纹和检查器规则指纹；任一变化、读取不完整或原文片段失效均不复用。纯导航调整也可能使整页指纹变化，这种保守失效优先于误用旧结论。未出现在本次范围内的记录提示为未复用，不代表其事实结论被否定；导出只包含当前扫描候选，不能直接覆盖全库旧记录。

有效正式记录在工作台显示为「已复核」，提议显示为「待人工确认」并继续计入待复核。所有证据诊断均接受 `supported`、`non-quantity`、`author-structure` 三种有效终局结论。直接陈述取得结论即可降级，派生或近似主张还须有有效的 `human_confirmation`。原为 🟡 的告警须全部候选符合条件才降为 🔵，即使剩下的待办候选原为蓝色建议也须等其结案。记录失效后按原始诊断定级。原始诊断、告警数和未定位回查队列均保留。它是有依据的复核结果展示，不是脚本的事实认证，也不是通用词语豁免。校准值和派生值缺少实际来源时保持 `pending`，不能通过复核文件绕过补充来源的要求。

已核对的校准值应摄入或引用支持采用值的实际 raw 证据，并让对应论断的脚注沿来源链到达它。只在页面 sources 中增加无关条目，或把依据写在知识库之外，不能替代该条引用。外部依据是否覆盖全部指标、期间和地域仍需逐项判断，不承诺加入一份公报就能消除所有单位候选。

新增派生值列出真实分量、方法与条件后，由自动复核提出结论，再经人工确认；lint 不证明一般算术，保留候选不等于已确认错误，也不应把自行计算的结果伪装成原始来源来消除提示。候选是否合理取决于是否指出具体风险、回查位置与处置动作，不能只看是否可以清零。未定位项按页列为复核队列，优先核对影响结论的主张，不只在高密度页面检查，也不把未定位整类认定为低价值噪声。

### 增量分类与人工确认

新模板增加 `review_policy: 2` 和只读 `category`。分类使用完整的脚注论断片段，不使用截短的报告上下文；复用记录时重新计算类别，改填类别不能绕过确认门。类别按下表顺序判定：

| category | 显式范围 | supported 条件 |
| -------- | -------- | -------- |
| derived | 复用既有校准、校正、更正、修正、派生及等式标记；另包括计算、估算、推算、推导、折算、换算、合计、总计、平均、增幅、降幅、增长率、占比、相差、之和、之差、乘以、除以及数字运算符；英文 calculated、derived、estimated、sum、average、ratio、rounded | 先提议，再人工确认 |
| approximate | 数量解析器已有的 approx、near 标记，含「约、大约、左右、上下、近」、英文近似词、带显式近似标记的时长（如「十余年」「约半年」「半年左右」）及相邻数量约数，也含 approximation-difference 诊断 | 先提议，再人工确认 |
| direct | 未命中上述标记的直接数值或引文陈述，含上下界、序数和普通日期 | 自动复核可直接 supported |

「十小时」等明确时长沿用数值和单位诊断。「十余年」等近似时长若未定位，须经确认才能降级。

派生优先于近似。同一片段含计算标记时保守按派生类处理。分类是显式语法约定，不证明隐藏推导不存在；复核中发现推导但缺少标记时保持 pending 并指出限制，不能当直接陈述自动批准。

- 自动复核对 derived、approximate 只能填 `proposed-supported`，同时填 `source_values`（原文数值）及 `derivation`（推导算式、单位与条件）或 `approximation_span`（原值到近似值的跨度、舍入或误差）。字段须为非空字符串，缺失时拒绝加载提议；原文引文仍按既有来源范围验证。derived 同时包含近似时，在 derivation 中一并说明近似过程。
- 人工确认指知识库指定复核者的逐条核验，具体身份由知识库 AGENTS 或用户指令约定，疑难时升级用户裁决。确认后将 status 改为 supported，并填 `human_confirmation: {"reviewer": "<指定复核者标识>", "confirmed_at": "实际 ISO 时间"}`；保留自动复核理由、原文及算式。工具验证状态字段，不连接独立审批系统，也不认证填表者身份；自动复核不得自行填写人工确认。
- 新模板所有复核字段均有空值占位。提议属于待办，既不降低证据告警级别，也不计为已复核；有确认信息但仍处于提议态同样不降级。真实错误保持 pending，并按实际问题另行报告，不能靠 supported 隐去其他诊断。
- 已明确完成全量回查的旧协议记录，由兼容配置中的 `legacy_review_rules` 指定其规则版本；这些版本可按原身份复用结论并计入已复核数。降级时仍检查派生和近似主张的人工确认字段。`review-compatibility.json` 按当前规则指纹明确列出兼容旧指纹，继续验证完整身份、内容哈希与证据。新版记录即使通过兼容映射复用，仍须满足类别与人工确认要求；新候选、旧 pending 或内容失配后的候选使用当前规则。未知或不兼容规则保守失效，不能为通过测试而自动扩展映射。

规则指纹由 `scripts/wiki_rule_fingerprint.py` 对证据相关源码的规范化 AST 与 schema 非 limits 结构计算。注释、docstring、位置和空的可选 AST 字段不参与；指纹覆盖路径解析、锚点判断、来源图构建及证据检查。索引、页面体积、冲突提示及日志逻辑位于独立的 lint 编排模块，调整这些检查可继续复用原有记录。新增依赖或影响证据语义的配置时须更新保护范围；跨 Python 版本升级应验证规范化结果，不承诺任意未来解析器都等价。兼容升级验证后显式登记映射，真实规则变化允许没有兼容映射。

### 自动复核负样本抽检

负样本必须满足「引文真实存在，推导有硬伤」。`scripts/review_quality.py` 提供 `audit_samples(samples, reviewer, weekly_pending=...)` 注入入口，reviewer 接收主张与原文并返回状态，不收到硬伤答案；也可用 CLI 统计保存的模型响应：

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/review_quality.py" /outside-kb/negative-samples.json --weekly-pending 12
```

输入为 JSON 数组，每项含唯一 id、category（derived 或 approximate）、claim、source、quote、flaw；离线统计另填 status（supported、proposed-supported、pending 或 unsupported）。样本设计者保证 flaw 为真实硬伤，工具验证 quote 确实存在于 source，不代替语义审查。

按类别分别统计误判支持数 / 该类别样本数，supported 和 proposed-supported 均算误判，阈值读取 `schema.json` 的 `limits.max_review_false_support_pct`（百分数）；无样本不算达标。不混合两类平均，也不把拒答或待复核计作误判支持。定期抽检，自动复核模型或提示词变化时复测并保留模型、提示词版本与抽检结果。平时只报告质量，不作为上线门槛；单周派生与近似待审合计超过 `limits.review_weekly_admission_threshold` 时恢复准入阀，两类均达标才允许自动提议。CLI 此时不达标返回 1，普通抽检返回 0，输入错误返回 2；调用自动复核的 Agent 须遵循 `automatic_proposals_allowed`，本期不内置模型调用、周期调度或完整样本库。

### 元数据与跨页复核入口

raw 的日期、采集时间和媒体时长可作为对应主张的复核依据。证据条目增加 `field`，`quote` 必须等于该字段完整的 YAML 标量值（去除外围 YAML 引号，保留原值写法），不能只取其中一个数字。当前支持 `timestamp`、`published_at`、`published_date`、`publication_date`、`published`、`captured_at`、`collected_at`、`duration`、`duration_seconds`、`video_duration`；缺失、复杂值、布尔值和空值不接受。其他自定义字段不自动推断含义。

- `timestamp` 表示采集时间，不能证明原文发布日期；发布时间不能证明录制时间。时区、日期换算、时长单位及元数据是否来自可信采集结果仍由复核者核对并写入 `reason`。
- 元数据只提供显式复核入口，不混入正文数值索引，不因字段里恰有同值就消除告警，也不作为作者逐字引文的依据。
- 复核绑定 raw 完整文件指纹，字段变化也会使旧记录失效；不以仅覆盖正文的 `body_sha256` 替代该指纹。

跨页来源原本即可通过 `sources[].resource` 指向知识页，再沿其来源链到达 raw。正文互文描述另可使用受限的复核入口：同一论断片段内有实际可解析的标准 Markdown 链接或 Wikilink 指向知识页时，证据条目增加 `via`，填写该知识页的知识库相对完整路径；`path` 仍须指向该页来源链中的 raw，`quote` 仍须实际存在。可与 `field` 组合使用。

- 只沿显式链接进入一页，再沿该页的 `sources` 追溯；不递归遍历相关阅读，不接受无链接的页名提及、全库同值搜索结果或库外文件。
- 入口限定在同一段落、列表项或表格行，且不得跨过逐条脚注的归因边界。相邻条目、代码、注释、图片、失效路径与失效锚点不授予取证范围。多个链接并存时由复核者核对实际归因，不能合并批准。
- 链接页须为摘要、实体、概念、分析或主题页，来源链完整且无循环，不得回到当前论断页来为自身作证。链接页及其传递来源都纳入复核依赖指纹。
- 此入口仅用于有实际依据的语义复核，不改变正文匹配范围，不豁免缺脚注、缺来源或来源冲突。正式新增或更新跨页论断仍优先维护 `sources` 与就地引用。

库外核验记录可作为补源线索，不能仅凭「已人工核验」或一个外部 URL 标为 supported。应将实际核验材料摄入 raw，记录出处、核验方法与适用范围，再建立来源关系；核验者自述不能替代其声称查阅的原始材料。未完成的项继续 pending，并注明具体缺口，而非认定为无风险。
