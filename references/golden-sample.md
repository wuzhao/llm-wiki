# Golden Sample 回归基线

本文件定义 LLM Wiki 的最小可运行示例，区分发布前的 Agent 语义回归与工具自动化回归。

## 目标

- 用最小输入覆盖 `init`、`ingest`、`synthesize`、`query`、`lint`、`explore` 六个 `workflow`
- 验证「`preflight` 硬校验 + `report-only` 默认 + `append-only` 日志 + 冲突保留」是否仍生效
- 提供可重复的通过标准，避免只靠主观判断

## Agent 语义回归

发布前在临时知识库执行场景 2、3、4、9、10：验证真实素材获取与完整性、术语提炼是否有实质内容、冲突双方是否忠实保留，以及后续素材能否补足旧主题并复用同义页。自动化只验证工具机制，不能替代这些内容判断。

其余场景的机制验证通过下文自动化矩阵执行；涉及来源归因、派生算式或人工确认的事实结论，仍由实际复核者负责。场景编号保持稳定，便于历史记录引用。

## 场景规格

场景 1：本地 Markdown 素材

- 输入：一篇本地技术笔记
- 预期：首次摄入生成 1 个 raw 页面，并建立或补充对应来源摘要；相同内容重复输入提醒已摄入并核对既有摘要
- 预期：修改原始本地文件后运行 `lint`，报告「🟡 中等」的原始文件变更提醒

场景 2：URL 素材

- 输入：1 个可访问 URL
- 预期：成功抓取并生成 raw/source；若抓取失败，明确报错并要求粘贴正文，且不写空文件

场景 3：粘贴文本素材

- 输入：一段带术语的纯文本
- 预期：检查核心实体、概念及相关历史摘要，按实际信息增量补充知识；满足建页门槛时当次新建 entity/concept，信息不足时保留候选及原因

场景 4：冲突素材

- 输入：两段对同一主题结论相反的内容
- 预期：保留冲突双方，不执行删旧保新

场景 5：`lint` 巡检

- 输入：对上述结果运行 `lint`
- 预期：默认仅报告；仅在显式 `--fix` 时执行安全修复，不做级联删除

场景 6：raw 元数据补齐与正文只读

- 输入：缺少 `type` 或 `title`、带来源地址与采集时间的 raw 页面，正文包含有唯一同名候选的失效链接与多行代码
- 预期：显式 `lint --fix` 仅补齐可确定的元数据，保留来源字段与未知字段，正文的链接、空白和换行逐字节不变；正文链接问题仍在报告中

场景 7：写后检查

- 输入：本次写入的 wiki 页面包含指向不存在页面的链接，另有不相关页面的历史问题
- 预期：`--lint-files <本次变更与受影响页面> --fail-on error` 返回 1 且不改文件，index 始终检查；Agent 核对修正本次问题后重查返回 0，再追加完成日志

场景 8：工作区技能与知识库分离

- 输入：技能安装在工作区局部目录，目标知识库在独立目录；路径含空格与中文，终端当前目录切换到另一个已初始化的知识库
- 预期：使用已确定解释器、技能脚本与目标知识库的绝对路径，摄入和修复只写目标知识库；搜索与影响分析读取正确目标，技能及另一个知识库均不改变
- 预期：缺少依赖时，报错指向实际运行的解释器和技能内的依赖文件，不能引导 Agent 在当前知识库目录查找同名依赖文件

场景 9：单篇充分与顺带提及

- 输入：一份只顺带提及术语的素材，以及一份对某工具提供用途、行为和限制的完整说明
- 预期：前者不创建占位页；有后续提炼价值时记录候选、原因和触发条件。后者无需等待更多来源或用户点名，当次建立实体页及有实质内容的概念页，保留来源

场景 10：跨篇补足与同义更新

- 输入：首次素材仅说明术语与对象的关系，后续素材提供其定义、机制或适用条件，并使用别名
- 预期：后续摄入检索历史摘要与暂缓候选，补足后建页，移除已处理候选；已有同义页面时更新它，不重复创建。跨篇页面说明关联、差异或条件，不只是拼接摘要

场景 11：首次历史回扫与中断恢复

- 输入：超过单批阅读量的旧摘要，缺少提炼状态，实体和概念目录为空
- 预期：立即触发历史回扫，分批阅读与记录；新进程只列出本轮未完成摘要。全部检查、来源链完整且写后检查通过后，检查点附在同一条事务日志中。未完成时不写检查点，不把剩余摘要当作已处理

场景 12：周期、去重与版本

- 输入：在已完成回扫后摄入重复素材、同文转载、仅修改导航，以及达到配置周期的不同来源正文或同一来源的不同正文版本
- 预期：前三者不推进周期；有效正文变化累计后触发下一轮，摘要只引用最新版也不遗漏中间版本。只复核变更、受影响及命中候选的摘要，无关旧摘要不重新入队；检查点只追加新指纹。数量不能强制产出页面或把多个版本当作独立证据

场景 13：记录异常与覆盖缺口

- 输入：候选缺少暂缓原因、检查指纹失效、目录读取失败或来源链无法到达 raw
- 预期：状态格式错误由工具和 lint 报告，内容变化进入待检查；工具不写文件、不生成完成检查点。`lint --fix` 不补造检查记录、不创建知识页；旧摘要没有状态不作为结构错误

场景 14：显式整理与只读边界

- 输入：未到周期时请求整理已有摘要；另行执行普通 query/explore
- 预期：整理使用 `synthesis_wiki.py --force` 并分批续扫，无需等待周期；普通查询和探索保持只读，不隐式维护知识页

场景 15：统一摄入入口

- 输入：通过 ingest 首次摄入素材，修改同一来源后再次摄入，再提供相同输入；另提供同标题但不同正文的粘贴文本，以及指定既有 `source_id` 的文本更新
- 预期：同一工具分别执行首次保存、版本追加和重复复用，保留历史 raw。来源正文变化必须执行影响分析与更新协议，重复输入仍需补完上次未完成的摘要、提炼或传播；新事务统一记录为 ingest
- 预期：同标题不自动合并来源，文本显式身份建立版本关系；同文不同出处保存来源但不冒充独立证据。重新摄入或重新投喂均执行 ingest，由实际变化决定动作，不强制新增版本或改写历史日志

场景 16：来源结构与引用粒度

- 输入：直接引用唯一 raw 的摘要，包含普通转述、无脚注的校准值、派生公式和直接引文；另有多源摘要、仅间接引用的摘要、单源概念页与含数字的聚合页。
- 预期：单源摘要的普通转述免于逐条脚注，但数值仍与唯一 raw 核对，未定位值继续报告证据待复核；校准、派生与直接引文仍提示缺脚注，未知 id 与缺失定义仍报错。其他事实页保持逐条引用，纯导航聚合页不被要求补造来源。默认 lint 不改写任何页面。

场景 17：证据候选分级与复核队列

- 输入：数值相同但只差「约、左右」的论断，以及含边界、序数、「近」、单位、直接引文和未定位人数或派生值的论断；同段混合两类候选，另有多段未定位值落在同一页。
- 预期：普通近似差异及仅单位省略或补全保留蓝色建议，不成为精确匹配；单位不同等实质差异及未定位计数保持黄色，混合项以最高级别计一次，详情保留各主张级别。同一主张的建议类候选不能掩盖并存的黄色候选。未定位值按页汇总且不增加告警数，默认检查不改文件；仅蓝色项不触发 `--fail-on warning`，黄色项仍触发。校准依据只有进入对应脚注的来源链才参与匹配。

场景 18：数量降噪与复核记录

- 输入：繁简数量、英文时长、跨语言文件计数、「两个月」「成千上万个」「4.5 上下文」，以及金额、人数、序数和年份缩写的负例。
- 预期：确定等价的数量匹配，跨语言通用计数只提供候选；不会截取月份计数、模糊量尾部或「上下文」作为数量限定。不豁免真实数量、顺序或年份歧义。
- 输入：同页重复候选，导出复核模板并填写真实原文依据，显式读取后再修改页面、传递来源或检查规则。
- 预期：模板默认 pending，工作台分组保留所有上下文；有效记录显示已复核，内容或规则改变后重新待复核。全程不改知识库，原始告警计数保留；所有候选均有有效终局结论且满足人工确认要求时，黄色证据告警降蓝，退出码使用调整后的级别。
- 输入与预期补充：`四五十个 Agent` 可定位到原文的 `四五十个AI agent` 或 `45个AI agent`；没有数量、区间外数值、单位不同、上下界限定均保留回查。原文约数不能反向支持摘要精确值，成语 `七上八下`、`十之八九` 不拆取数量。日志按 schema 配置的 UTF-8 字节限额检查，刚好达到限额不报警，超出后保持蓝色建议。

场景 19：修复预览与概览覆盖

- 输入：缺少 frontmatter、链接路径错误、索引缺条目的知识页，以及需要人工判断的条目。另有正文命中查询词、为空或已经过期的 overview。
- 预期：`lint --fix --dry-run` 列出实际可执行的修复计划及剩余人工项，文件和日志字节不变，`--fail-on` 不把计划修复当作已完成；YAML 引用保护和扫描缺口保护同样生效。实际修复与预览计划一致。
- 预期：overview 参与正文搜索、空正文、体积、冲突与生命周期检查，但不要求进入分类索引，也不计入知识入链或孤儿页。

场景 20：相邻列表与表格引用边界

- 输入：相邻列表项含相同数值，只有后一项有脚注；另有列表内换行、嵌套列表和没有共享来源声明的相邻表格行。
- 预期：后一项的脚注不能覆盖前一项，前项继续报告缺少逐条来源；同一列表项内的连续换行可以共用末尾脚注，子列表独立检查。没有显式共享来源声明的表格逐行检查；已有显式表格来源规则继续生效。

场景 21：来源位置迁移

- 输入：摄入库内文件后搬动完整临时知识库；外部文件或 URL 换位置后，以旧 raw 的 `source_id` 再次摄入。
- 预期：库内相对位置继续可用，已有身份保持不变；明确迁移保留旧 raw 并追加新位置的版本，相同位置的重试不写入。多个身份占用同一位置时停止写入，要求明确选择；无身份的旧素材继续兼容原推导规则。

场景 22：摘要报告、详情筛选与复核复用

- 输入：含多个页面、严重问题和证据候选的知识库，分别运行默认报告、完整详情、页面与类别筛选、完整导出和修复预览；部分或全部候选附有效复核记录。
- 预期：默认报告保留全局计数与所有严重问题，详细证据按需展开；筛选只改变显示，完整导出、修复范围及退出码不受影响。同一问题跨视图使用相同 id，计划修复与已修复明确区分。
- 预期：原始告警数、已复核主张数和仍待复核数分别显示，部分复核不标为整条完成；有效记录复用，来源或规则变化即失效。只读报告和复核复用不改知识库，严格退出码按复核后的实际级别计算，其他类别不变。

场景 23：元数据与跨页复核

- 输入：主张的发布时间、采集时间或视频时长仅在 raw 的标量字段中；另有同一段落、列表项或表格行内显式链接到姊妹页的转述，证据在姊妹页的传递 raw 中。
- 预期：报告和复核模板列出字段与跨页入口；经语义核对后，`field` 加完整字段值或 `via` 加真实 raw 片段可复用，二者可以组合。仅元数据同值或链接存在不自动批准，原始告警保留，使用复核后的证据告警级别计算退出码。
- 反例：字段错配、只截取字段值的一部分、任意人数元数据、无关页面或库外路径、相邻段落与列表项或表格行、代码与图片中的链接、跨脚注归因、失效锚点、循环或不完整来源链都不能扩大取证范围。元数据、跨页中间页或 raw 变化后记录失效；全程不改写知识库。

场景 24：引用片段与来源变更分流

- 输入：通过 `impact_wiki.py --heading` 记录一个或多个引用章节，分别修改未引用的维护章节、被引用的正文与子章节、上级标题；另有标题改名、同名歧义、无效记录与只存整页哈希的旧页。
- 预期：未引用章节变化仅提示蓝色，片段或上级标题变化保持黄色并定位当前行；无法定位、无效记录与缺少片段信息时保守复核。片段行号平移不失效；只统一行尾编码及片段边界空行，内部空白、代码与脚注仍参与指纹。所选片段必须全部匹配。
- 预期：蓝色依赖提示不触发 `--fail-on warning`，黄色仍触发并传递至归档分析；中间页的未变片段不能遮住上游风险，raw 新版本仍须复核，历史依赖不传播。影响分析和 lint 均只读，默认不生成或刷新片段快照。

场景 25：证据复核分级与增量确认

- 输入：当前哈希绑定的 supported、non-quantity 或 author-structure、新增直接陈述、新增派生及近似主张；修改页面或来源；同一告警内混合其他黄色诊断。
- 预期：黄色证据主张按有效终局结论降蓝，队列及原始告警数不变，存量无需迁移；哈希或规则失配恢复黄色。直接陈述可自动 supported；派生、近似缺少原文数值或算式、跨度时拒绝提议，提议不降级且计入待复核，人工确认转正后才降蓝。原为黄色的混合告警须全部候选符合降级条件，其他类别沿用原级别；全程不改用户知识库或既有复核文件。
- 输入：按类别注入真实引文但推导错误的负样本。
- 预期：支持与提议均计误判，分类别统计并使用 schema 的最大误判百分比，空类别不算通过；常规只抽检，单周待审超过 schema 的准入阈值时才作为自动提议准入阀，模型或提示词变更须复测。

## 通过标准

- `preflight` 缺失关键结构时立即停止写入
- 每个产生文件变更的 workflow 事务追加一条汇总日志到 `wiki/logs/YYYYMM.md`（当月文件）
- 所有新增或改写的概念页 `frontmatter` 可 YAML 解析且 `type` 非空；根 index 只包含 `okf_version`
- `lint --fix` 不删除 source/entity/concept 页面，不清理历史日志
- 出现冲突时，页面包含冲突标注和来源
- raw 元数据补齐保留来源信息与正文；所有写入 wiki 的业务 workflow 在完成日志前执行只读写后检查
- 主题检查有可恢复记录；满足门槛时生成或维护知识页，证据不足时有明确暂缓原因，不以每批产出数量作为通过条件
- 增量复核周期与阅读批次读取 schema；周期检查点不宣称完成全库语义检查

## 发布前最小回归清单

- 第 1 步：执行自动化回归：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`。
- 第 2 步：执行需要 Agent 语义参与的场景 2、场景 3、场景 4、场景 9 和场景 10，并按下文矩阵核对所有场景的工具覆盖；语义内容由 Agent 实际判断。
- 第 3 步：核对「通过标准」每一项是否满足。
- 第 4 步：将结果写入迁移记录或发布说明，注明失败项与处理结论。

## 自动化覆盖说明

自动化用例以 `tests/` 为准；发布前同时运行 `scripts/check_project.py`，检查 schema、技能 frontmatter、护栏数量、模板类型与版本、Markdown 结尾、中文正文标点、分隔线、表格加粗与明确数值列对齐、本地文档链接和阈值定义。代码、注释、frontmatter 和链接目标不作正文排版判断；混合文本列不猜测数值语义。GitHub Actions 执行同一检查。

- 摄入与附件：来源身份、重复输入、版本保留、原始响应与附件字节、附件关联、失败不落盘和并发创建。
- 初始化：真实工具与测试共用实现，空目录校验、渲染失败与安装失败保留目标。
- 检查与修复：raw 正文、未知字段、代码与注释保持完整；链接根语义、锚点、索引、来源链及作用域正确；扫描缺口停止修复；外部原文件丢失可按模式分级。
- 提炼：首次全库检查、增量范围、候选重新触发、批次输出、中断恢复、v1 兼容和 v2 增量检查点，错误状态不产生完成记录。
- 写入：修复计划拒绝覆盖扫描后的编辑，日志只追加，部分失败如实报告。
- 查询：正文与别名命中、分页、会话复用、读取错误及只读边界。

历史验证结果见 [维护验证历史](../docs/maintenance-history.md)，日常回归无需加载。
