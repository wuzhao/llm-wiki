# Query Policy

## 默认行为

- 读取并综合知识库内容回答问题。
- 默认不写文件。

## 查询步骤

1. 先读 `wiki/index.md` 定位候选页面。
2. 对问题关键词、实体别名和同义词执行正文搜索，不能只依赖索引中的单句摘要。
3. 使用工具默认批次大小读取相关 wiki 页面；手工分批时读取 `schema.json` 的 `max_query_read_pages`。保留已读路径与阶段性结论，继续读取直到证据足够或确有信息缺口。
4. 重要数值、冲突和依赖待复核的结论按 `provenance-policy.md` 回查 raw；引用不能停留在无原始证据的派生页面。
5. 产出回答并给出页面引用，明确不确定点、冲突点、知识空白和实际覆盖范围。

## 全文搜索与分批推进

```bash
"<PYTHON>" "<SKILL_DIR>/scripts/search_wiki.py" "<KB_DIR>" "关键词" "同义词" --offset 0
```

- 结果包含命中行、片段、匹配词、正文或元数据命中类型，以及下一批的 `next_offset`；支持 `--type`、`--tag`、`--domain` 过滤和 `--limit` 批次大小。
- 搜索读取可用的 `title` 与 `aliases` 扩展明确别名。Agent 仍须补充领域同义词；别名相同只代表检索候选，不能据此合并不同实体。
- 还有候选时使用 `next_offset` 继续读取。批次预算不是整个问题的总页数上限，不因超过一批就要求用户缩小问题。
- 多批查询可添加 `--interactive`，在同一进程内复用候选列表。首次及后续响应各占一行 JSON；向 stdin 发送 `{"offset": <next_offset>}` 读取下一批，可同时传 `limit`。EOF 结束会话，不写缓存文件。
- 会话基于首次搜索的内容快照；资料变动后发送 `{"refresh": true, "offset": 0}` 重新搜索，再按新结果继续分页。单次调用与 `--offset` 方式继续保留，但每次启动都会重新搜索。
- 索引和正文搜索均未命中，且没有未处理的读取错误时，才可以说明知识库没有找到相关内容。`read_errors` 包含文件读取和子目录遍历失败；有错误时命令返回 1，即使结果为空也只代表已读范围内无命中。说明覆盖限制，并使用 `rg` 或直接读取相关文件核查。
- 问题本身含糊或仍有无法解决的证据分歧时再请求澄清；默认保持只读。

## 引用规范

- 对话输出引用使用项目相对路径。
- wiki 文件内引用使用相对路径。

## 归档（仅在用户明确要求时）

当用户明确说「归档/保存」时：

- 新建 `wiki/analyses/YYYYMMDD - <topic>.md`
- 不合并进既有实体或概念页
- 按 `lint-policy.md` 执行共用写入收尾

归档模板见根目录 `templates/archive-template.md`。

归档页 frontmatter 遵循 `okf-frontmatter.md`。
